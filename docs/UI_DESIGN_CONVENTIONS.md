# Tsuki 界面设计约定

应用内界面以 HyperOS 4 系统应用为风格参考；桌面小部件的布局与资源受已安装实例兼容约束。不可放宽的边界见 [DEVELOPMENT_CONSTRAINTS.md](DEVELOPMENT_CONSTRAINTS.md)。

## 应用内组件

### 设计原则

- 单一 app 模块，固定 Miuix 0.9.4。颜色取自 `MiuixTheme.colorScheme`，字号取自 `textStyles`；应用主题通过 `TsukiTextStyles` 统一缩小，仅改字号，保留默认字重和行高。桌面字号投影仍使用 Miuix 默认值。基础行、卡片、标题和弹层使用库 Defaults。明确规格中的胶囊、指标大数字等尺寸在对应小组件实现，不复制或修改库组件。
- 三标签为概览、部件、我的，图标为 Home / All / ContactsCircle。页面可通过底栏或横向滑动切换，以 Pager 最终停留的页同步底栏与当前页；每页独立保存列表位置并在重建后恢复；`initialPage` 0/1/2 对应三个标签，旧 3 进入我的并定位外观。
- 页面居中且不超过 600dp，消费真实 systemBars（状态栏与标题栏、导航栏）、横向安全区和 IME Insets；顶部 Inset 与 Miuix TopAppBar 一致，统一由 `topBarInset()`／`bottomBarInset()` 取得。添加入口在顶栏；无 FAB。列表底部为底部 Inset + 100dp；底栏距底部安全区 2dp。
- 二级页面（数据与隐私、开源许可、添加账号、选择平台、网页登录、通知提醒及其账号页）统一使用 `SecondaryScaffold`：与三标签相同的“内容 → 顶部玻璃 → 透明 TopAppBar”叠放、同一玻璃后端顺序与渐隐参数；标题同时作为无障碍窗格标题。网页登录使用紧凑变体（C13）。二级页面在同一窗口内滑入，转场效果统一取自 `tsukiNavEffects()`：进入页的前缘两角按屏幕圆角（`rememberNavSystemCornerRadius()`）裁切，与 HyperOS 的 Activity 窗口转场一致，已在实机上按截图测量核对；转场中屏蔽输入。不使用预测性返回：清单中 `android:enableOnBackInvokedCallback="false"`，返回手势只在松手时执行，页面按普通转场退出，不跟手预览，根页面返回桌面也没有系统预览动画。支持 HyperOS 4 的“点击状态栏回到顶部”：三个主页面和可滚动的二级页面会把列表滚回第一项并展开大标题（`ScrollToTopEffect`）；网页登录页交给系统直接滚动 WebView。转场期间按钮、输入框和返回键保持正常外观，只在真正忙碌时显示为禁用；点击要等页面可交互才生效（`SecondaryScaffold` 的返回键按 `active` 拦截，各页面的操作按自己的 ready 判断）。数据与隐私、开源许可使用 `InfoPage` 的文档式版式：顶部文档卡片（title4 粗体标题、footnote1 的适用版本与更新日期、body2 引言），随后是编号的 TsukiSmallTitle 分节与卡片行，末尾为 footnote1 说明。其他页面不使用整段说明文字。
- 分组标题一律使用 `TsukiSmallTitle`，不直接用 Miuix `SmallTitle`，也不在页面里自己拼：footnote1 字号（12sp）粗体，onBackgroundVariant 色（SmallTitle 的默认色；SmallTitle 固定用 subtitle 的 14sp，不接受字号参数，所以组件用 Miuix `Text`），水平 16dp（与列表 12dp 合计 28dp，与卡片里行文字的起点对齐）。标题按墨迹定位：墨迹上沿在上方卡片下沿以下 21.1dp，墨迹下沿在下方卡片上沿以上 10.1dp；页面以分组标题开头时，墨迹上沿在内容起点（C1）以下 9.6dp。标题紧贴在它的卡片（或输入框）上方，所在列表或列已经加上的间距由调用处告诉组件，组件只补差额，所以各页的最终距离相同：主页面列表 `spacingAbove = PageListSpacing`（10dp），添加账号表单 8dp，间距为 0 的二级页面（数据与隐私、开源许可、通知提醒）用默认值；卡片是下一个列表项时传 `spacingBelow`（“我的”的“森空岛账号”），页面开头的标题传 `first`（“我的”的“森空岛账号”、选择平台、通知提醒账号页的第一个角色）。依据：系统“设置 › 更多设置”截图（2026-11-20，3.25 px/dp）：标题汉字步进 40 px（约 12.3sp，最接近的字号是 footnote1），粗体，蓝灰色（约 #909BAB，接近 onBackgroundVariant），起点与卡片里的行文字相同；卡片下沿到墨迹 68.6 px，墨迹到下一张卡片 32.9 px，第一个标题的墨迹在内容起点下方约 31 px。12sp 文字的行框在参照机上墨迹距行顶 0.19 em、距行底 0.21 em（按 Tsuki 部件页 12sp 名称逐像素实测），组件按此换算内边距。列表行之间不加分隔线。仅菜单分组之间使用 dividerLine。不添加设置项摘要或非必要说明（通知提醒页账号行的摘要是这个账号当前开启的提醒数，如“已开启 2 项提醒”，不是说明文字，不在此列）；保留同步时间、失败原因、倒计时、必要的权限与错误文案，以及 Cred 输入框下方那段获取方法与安全提示。
- 《明日方舟》概览按 realtimeLabels / buildingLabels 的顺序显示全部指标；终末地概览（`endfieldOverview`）先是理智卡片，其余各项按森空岛中设置的顺序列在一张卡片里。缺失数据为“未知”；倒计时使用 Dashboard 中的函数，绝对恢复时间和同步年龄使用可测纯函数。完成状态回答大致的“现在是否完成”：根据有效的恢复或完成时间推算到点后，可以直接显示“已满”“已完成”，不强制区分“预计”与“确认”；内部仍保留来源和时间，刷新后按新数据校准，未知数据不当作完成。训练头像使用 roundedAvatar(1 / 9.5) + trainingPortrait 的正方形裁切。官方玩家头像自带的暗色相框在圆角裁切前按像素检测去除（`bakedFrameInset`，每边最多 10%，透明边缘与普通图片不裁）。
- 小部件预览统一经 `WidgetPreviewImage` 绘制真实位图（同一渲染源、位图缓存与淡入），不放图标占位；位图自带部件的圆角，周围是与 HyperOS 系统小部件预览一致的柔和投影（`dropShadow`，黑色，半径 20dp、下移 6dp，浅色 10%／深色 30%），不使用随光源位置变化的高程阴影。部件页与部件面板用 `ScaledWidgetPreview`：预览直接放在背景上，没有卡片和舞台，宽度为所在页面或面板宽度的 82.3%，居中（C16）；概览空状态仍用 `WidgetPreviewStage`，预览放在舞台上（上下内边距 14dp）。部件页两个标签用同一个条目 `WidgetGalleryItem`（C16）：预览，预览正下方居中的粗体名称，名称与桌面小部件列表同名（“明日方舟数据工具”“明日方舟：终末地数据工具”；《明日方舟》的浅色与深色两个部件与官方小组件一样同名，部件页、部件面板与桌面列表都只能靠预览区分），系统列表的“应用 · 部件名”格式不用；已添加的部件只在刷新失败时在名称下方居中显示原因（error 色）。按下整个条目时只有预览缩小，名称与失败原因不动，松手回弹后再打开部件面板。“全部小部件”始终列出所有游戏的全部小部件，不随概览的游戏标签变化，每个预览用该游戏上次查看的角色的缓存数据；概览切换游戏时，卡片以与部件页标签切换相同的时长（C14）淡入淡出，已读过的角色数据在进程内缓存，切回时立即显示；除《明日方舟》外，各游戏的小部件照官方外观只有一种，部件面板不显示配色。
- 部件面板 `WidgetSheet`（`OverlayBottomSheet`，几乎占满屏幕，C17）有两种头部。从“全部小部件”进入是新建：左上返回，标题行中间是游戏标志与游戏名，下面是大号粗体的部件名和一行说明（与桌面小部件列表的描述相同），底部主按钮“添加到桌面”。已放置的实例（从“已添加”进入，或从桌面的配置入口打开，包括尚未配置的实例）是编辑：左上关闭，标题“编辑小部件”，主按钮“应用”。头部下面是大号预览，再下面是设置行，直接排在面板背景上、不套卡片，横贯面板全宽，按下时的灰色高亮贯穿屏幕，文字仍与主按钮对齐：角色与配色使用文字下拉菜单。保留 hostProvider 材质提示、Debug 模拟失败、没有账号时的“请先添加森空岛账号／添加账号”、主按钮上方的内联错误及忙碌保护（忙碌时主按钮、返回或关闭以及下拉关闭都不可用）。新建配置且角色匹配时先使用概览已加载快照，随后沿用部件面板刷新。保存与放置流程见[开发约束 §4](DEVELOPMENT_CONSTRAINTS.md#4-部件放置)。
- 我的集中账号、外观、通知、关于；“通知”分组只有一行“通知提醒”，进入同名二级页。更多菜单提供更新 Cred / 删除账号，更新沿用添加流程，预填名称；Cred 输入框为空，占位文字为“留空则不修改当前 Cred”，留空提交时用已保存的 Cred 重新验证。已有 AUTH_EXPIRED 缓存可显示“需重新授权”，不为状态标记发送请求。开发诊断必须同时满足 Debug 与 diagnostics=true。
- 通知提醒页自上而下：总开关“通知提醒”（打开时如未授予通知权限即申请）；“状态”分组只在总开关打开且有问题时出现，每个问题一行（通知权限未开启、某款游戏的通知渠道已关闭），点开对应的系统设置页；然后是“森空岛账号”分组：一张卡片按“我的”页的顺序列出所有账号，每个账号一行 `AccountRow`（与“我的”页账号卡片的标题行是同一个组件：40dp 平台标志、账号名称与摘要，账号名称同样取 `accountTitle`），右侧是 `ArrowPreference` 的箭头，点开进入这个账号的二级页；摘要是这个账号当前开启的提醒数（“已开启 2 项提醒”，没有时“未开启提醒”，账号下没有角色时“没有角色”）。各项提醒都在账号页里设置，主页面不列出角色。没有账号时这一部分只有一张卡片“添加账号后可以设置提醒”。最后是“后台运行”分组：卡片里只有“应用信息”一行，必要的权限说明在卡片下方（footnote1）。
- 账号页（`ReminderAccountPage`，路由 `AppRoute.ReminderAccount` 只记账号 ID，随重建恢复）的标题是账号名称；账号被删除或不再列出时自动返回。页内是这个账号下的角色，先按游戏（《明日方舟》、终末地）、再按角色在列表中的顺序（调试夹具不列），每个角色一个分组标题“{角色名}（{游戏名}）”（同一账号下同名时在后面加服务器与 UID）和一张卡片，按 `ReminderOptions.rows` 每项指标一行（《明日方舟》：理智、无人机、休息进度、订单进度、制造进度、训练室专精、公开招募；终末地：理智、活跃度、每周事务、通行证）；账号下没有角色时只有一张卡片“这个账号下没有角色”。只有一种模式的两项是 `SwitchPreference`（“训练室专精训练完成”“公开招募全部完成”），打开即保存该模式，关闭即删除规则。其余指标各是一行文字下拉（`TsukiDropdownPreference`，C6，与配置面板的“角色”“配色”相同），标题为指标名，选项依次是“关闭”和当前上限允许的条件“已满时提醒”“达到百分比时提醒”“达到数值时提醒”（上限未知时没有前两种；已保存但当前不允许的条件也列出并选中，它的阈值行禁用，只能原样保留或改选其他条件）；下拉显示的值就是当前条件，不另加摘要。选“关闭”即删除规则；选条件即保存，阈值取该条件的默认值（百分比 80，数值取当前上限，上限未知时 1），本次运行中切回之前用过的条件时，恢复它当时的阈值（仍在合法范围内时）。规则的设置都在这一页内完成，没有弹窗、底部面板或输入框。
- 条件为百分比或数值时，紧接在下拉行下面、同一张卡片里展开阈值（`AnimatedVisibility` 默认的纵向展开与淡入；改选已满或关闭时收起，收起过程中仍显示原来的阈值）：一个滑块（`LabeledSlider`，C15），上方没有“阈值”标题，也没有当前值；滑块下方一行，左侧是当前值（“80%”，数值为“160”，拖动时跟着变），右侧是轨道终点（“100%”或上限，如“210”），两端标注都不贴着滑块两端（位置见 C15）。滑块的轨道就是合法范围（百分比 1 到 100，数值 1 到上限），整数步进，`steps` 为上限减下限再减 1，不设关键点；触感用 Step，每一档一次（Miuix 设了关键点时只在关键点触感，所以不设），只有两个取值时用 Edge，只在两端。拖动只改显示，松手保存一次（与已保存的阈值相同时不写）；无障碍服务调整滑块时没有松手事件，没有手指按住时的调整在停止约 400ms 后保存一次。阈值只用滑块调整，唯一的例外是上限未知的数值条件（例如制造容量未知）：没有上限就画不出轨道，阈值是一行“阈值”，右侧是数值与“−”“+”两个 `IconButton`（`MiuixIcons.Remove`、`MiuixIcons.Add`，无障碍描述“减少”“增加”），每点一下改一格，下限 1、没有上限，到达端点时对应的按钮禁用；连续点按时数值即时变化，停止点按约 400ms 后保存一次（`ReminderSettings.SAVE_DELAY_MILLIS`）。上限为 1 时只有一个合法值，“阈值”行只显示数值。依据：Android 原生设置“省电模式”的“设置时间表”在同一页上选中“根据电量百分比”后，下面立刻出现“电量为 X% 时开启”的滑块，不弹窗；Snap Hutao 的实时便笺提醒为每个账号一组设置，树脂等阈值直接用滑块调，开关类提醒用开关；Material Design 的离散滑块要求需要精确值时当前数值一直可见，每一档都让用户能感知到；Apple HIG 认为滑块适合连续调整并即时看到结果，步进按钮本身不显示数值，要把数值显示在旁边（上限未知时的“−”“+”照此把数值放在左侧）。
- 总开关关闭时其余各项照常可编辑、不置灰。写操作进行中，这项指标的行（下拉、开关、滑块与“−”“+”）保持可用的外观，只是在保存返回之前不接受这项指标的下一次操作：保存只要几十到几百毫秒，期间把行设为禁用会让文字先变成禁用色再变回来，看起来像先消失后出现。下拉选择后，值立即显示为新条件。失败时 Toast“保存失败”并恢复为组件进程返回的状态；两个页面回到前台时都重读状态。各项的上限只读各角色的缓存快照，进入账号页时为它的每个角色读一次。Tsuki 不修改系统设置，边界见[开发约束 §2](DEVELOPMENT_CONSTRAINTS.md#2-进程边界)。
- 添加账号的“授权信息”分组先是“在森空岛网页登录”行，再是 Cred 输入框；账号名称标为可选，输入限制在 40 个字符以内；取得 Cred（网页登录、粘贴或输入，停顿 800ms 后）时名称框为空，就自动填入森空岛昵称，用户已填的不覆盖，取不到时留空，不提示（边界见[开发约束 §3](DEVELOPMENT_CONSTRAINTS.md#3-凭据与账号数据)）。网页登录取得 Cred 后返回添加页，把 Cred 回填到输入框并用 Toast 提示，由用户确认后点击提交，不自动提交。本地校验（例如 Cred 无效、剪贴板为空）用系统 Toast 提示；平台验证失败的原因显示在表单下方。验证失败时保留已填写的 Cred，添加成功后清空。网页登录页打开的是电脑版页面，先缩小到适合屏幕的比例，可以双指缩放；系统返回先在网页内后退，顶栏返回直接离开；加载失败时显示一行错误和“重试”。
- Cred 只保留在内存，AccountDraft Saver 只保存名称和正在更新的账号 ID。顶栏 Ok 与“验证并添加”共用 save / ready，保留 IME 返回、转场门控、删除与重置确认、桌面快捷方式权限和两个 Activity 入口返回协议。

### 玻璃范围与回退

- 策略：所有页面（含首页）的顶栏背景、顶栏按钮、游戏胶囊和底栏都优先 HyperOS MiGlass，缺少能力或初始化／更新失败时回退 miuix-blur，再回退现有不透明外观。渐进模糊不作顶栏背景的首选：实机上（2026-11-15）miuix-blur 的渐进模糊在滚动时闪动（内容每滚 1 px，顶部模糊区亮度变化 3–8 级，图案不随内容平移），清晰端是降采样图层放大的，文字发虚带块状。边界见 [开发约束 §6](DEVELOPMENT_CONSTRAINTS.md#6-模糊与-hyperos-原生玻璃)。
- miuix-blur 依赖 `top.yukonga.miuix.kmp:miuix-blur:0.9.4`，使用公开 `rememberLayerBackdrop`、`layerBackdrop`、`drawBackdrop`、`progressiveBlur`、`blur`、`colorControls` 和支持性判断。一个主框架在 HorizontalPager 外最多记录单一容器，不在相邻页分别注册 backdrop；各表面报告实际后端，仅有 miuix-blur 消费者时录制，回退恢复录制；离开当前导航页后停止采样。
- 可以模糊的范围、反射调用与自写模糊管线的禁令见[开发约束 §6](DEVELOPMENT_CONSTRAINTS.md#6-模糊与-hyperos-原生玻璃)，本节只记录各表面的参数。
- 背景组合集中在 `ui/glass/TsukiGlass.kt`，原生顶栏承载层为 `NativeTopGlass.kt`，顶栏背景的几何与半径在 `TopGlassCurve.kt`，按钮／胶囊／底栏参数在 `GlassSurfaces.kt`，投影在 `GlassShadows.kt`，宿主与后端选择在 `GlassHost.kt`。
- **顶栏背景**：参照 HyperOS 4 系统主题商店首页的玻璃态（2026-11-14 实测，浅色与深色逐段一致）：没有蒙色，模糊后的内容直接透出；最强处高斯 σ 约 31 px（约 9.5dp），向下减弱，到胶囊行底边下方约 8dp 恢复清晰，最后一段与清晰画面交叉淡出。
  - **MiGlass（首选）**：复用胶囊配方，采用矩形轮廓、shape.edge=1、关闭胶囊增强；无蒙色；模糊半径 14（MiGlass 像素半径 64），满强度 σ 约 30 px，落在系统最强处的 28–31 px 内。真机标定（2026-11-16）：半径 17（像素半径 78）时满强度 σ 实测 37 px，浅色与深色、首页与其他页面相同，即 σ ≈ 0.475 × MiGlass 像素半径，而不是原先按底栏估计的 σ ≈ 1.8 × 半径，比系统强约 20–30%，所以改为 14。MiGlass 的半径不能随位置变化，所以已采样的结果用 DstIn 按 smoothstep（33 个缓存色标）淡出，淡出段内是“模糊画面 × 透明度 + 清晰画面 ×（1 − 透明度）”：首页概览在操作行底边以上为全强度，从操作行底边淡出到游戏胶囊底边下方 8dp（操作行底边下方 50dp）；其他页面在操作行底边上方 16dp 以上为全强度（居中标题的墨迹在其上方，标题背后不透出清晰内容），从那里淡出到操作行底边下方 8dp。原生材质的上、左、右边缘各向窗口外延伸 2 个物理像素，遮罩坐标不变，避免第 0 行和最外一列露出未经模糊的内容；不扩展页面布局或触控区域。顶栏原生实例在首页与其他主页面复用，进度为 0 时保持 INVISIBLE。矩形顶栏参数由胶囊配方派生并弱化边缘项，不是厂商提供的矩形标准配方，兼容性以实机验证为界。
  - **miuix-blur（回退）**：`progressiveBlur`，基准半径 10dp，从顶端到状态栏底边下方 6dp 为最强，到顶栏背景的底边强度降为 0，curve 0.55；无蒙色，不改饱和度。基准半径由按系统读数拟合的 23.25dp 降到 10dp（2026-11-15）：降采样倍数随半径增大，大半径在滚动时闪动、清晰端发虚；10dp 降采样更少，但这条路径在滚动时仍可能有轻微闪动。不传 progressiveGradient 时，渐进模糊的清晰端仍带降采样的柔化，所以已采样的结果在顶栏背景的最后 8dp 内用 DstIn 按 smoothstep 淡出，露出下方清晰的页面。
  - 两条路径的底边都是清晰线：首页概览在游戏胶囊底边下方 8dp，其他页面在操作行底边下方 8dp。滚动进度只乘在 DstIn 遮罩上，不改变模糊半径。玻璃不模糊前景标题（标题自身的过渡模糊见 C1）。
  - **已知差异**：MiGlass 顶栏会非线性地压暗中间调，白处几乎不变：满强度下平色 119 变为 81、247 变为 241，浅色与深色相同；系统主题商店的顶栏没有这种压暗。原因在顶栏复用的胶囊配方的色调，具体参数未查明，本版本不补偿。miuix-blur 回退路径没有这种压暗。
- 按钮、胶囊本体和底栏同样 MiGlass 优先。仅存在实际 miuix 消费者时启用 backdrop 录制；顶栏背景走原生路径时不是消费者。drawBackdrop 不传 progressiveGradient，不使用多档合成，不自写着色器。模糊关闭、回退和文字清晰边界不变。空间遮罩与不透明回退的渐隐使用缓存的 33 个 smoothstep 色标。
- 顶部背景透明度按 smoothstep(clamp(collapsedFraction × 3)) 连续跟随滚动，主页面首个可见项 > 0 时为全强度；在绘制阶段读取进度，不因此逐帧重组页面。游戏胶囊与顶部背景共用连续滚动进度，在胶囊组件内读取，避免重组整页；按钮仍沿用标题阈值与 folmeSpring(damping=1, response=0.3/0.15)。
- 游戏胶囊的颜色参照 HyperOS 4 系统主题商店胶囊静止态的录屏测量（2026-11-14），亮度按 (299R + 587G + 114B) / 1000 计。未选中胶囊静止为不透明色：浅色 surfaceContainerHigh；深色在 surface 与 surfaceContainerHigh 之间按 Oklab 插值取 66%，黑底上亮度约 16。未选中胶囊的玻璃态与底栏是同一材质：系统主题商店的胶囊一开始滚动就整体切换为与底栏相同的材质（2026-11-14 实测，浅色平页上透出斜率约 0.47，按原生模型反推底色约 63–68%；深色约 51–55%）。Tsuki 固定 14dp / saturation 1.8，浅色底色直接取底栏在各后端上的值（原生路径 surfaceContainer 65%、miuix-blur 41%），深色为 surfaceContainer 向 onSurface 混入 4% 后的 55%（约 #2C2C2C）；系统胶囊的模糊 σ 未能可靠测定，半径按底栏取值，待实机标定。外沿内侧有边缘光效（见下方“边缘光效”），没有投影（有两个以上胶囊时，未选中胶囊下方的投影会晕到下面的内容上）。选中底色先将 onSurface 合成到 surface 成为不透明色：浅色 77%（亮度约 57），深色 95%（约 230）；玻璃态使用固定 20dp 模糊，浅色保持完全不透明，深色为 94% 不透明度（系统浅色透出不到 3%，深色约 6.5%），没有边缘光效或描边。选中胶囊四周有外部投影，静止、玻璃态与模糊关闭时都有（见下方“投影”）。文字始终清晰。
- 按钮固定 20dp / saturation 1.6；底栏固定 14dp / saturation 1.8（原生路径经 110/24 换算约 64px），外部投影位于材质层之外（见下方“投影”）。底栏本体浅色原生路径白色叠加 65%、miuix-blur 41%（与原生保持同样的比例），深色两种后端 52%；外沿内侧有均匀的边缘光效（见下方“边缘光效”）。依据（维护者 2026-11-14 选定）：参照 HyperOS 4 系统电话应用底栏测量，模糊 σ 约 25px，对应半径 14；浅色底色 65% 取其大面积透出（约 69%）与细节透出（约 62%）之间的折中；系统电话应用与主题商店的底栏压在纯黑页面上本体亮度均为 21（2026-11-14 录屏测量），深色 52% 按此取值。实机按三种后端测量胶囊与页面的亮度差（2026-11-14）：浅色纯色页面上胶囊不暗于页面，白底（#FDFDFD）原生 +0、miuix-blur +1、不透明 +2 亮度级，#F2F2F2 底依次 +5、+5、+13；深色黑底两种模糊后端均为 +20，不透明 +36（深色读数为 2026-11-15 实测）。验收要求浅色下三种后端都不暗于页面超过 3 级。玻璃选中叠色为 onSurface 浅色6%／深色12%。进度只改变采样后透明度、色调、描边、边缘光效与阴影，不改变模糊半径。
- **投影**：参照 HyperOS 4 系统主题商店的录屏测量（2026-11-14，浅色，页面亮度约 243，读数为相对页面的变暗量，误差约 ±2 级）。底栏上缘外贴边 −8.5、20 px −6.9、40 px −5.0、60 px −4.2、80 px −3.1，两端外贴边 −7、20 px −5.3、40 px −3.4、60 px −2，上下对称、不向下偏移；选中的胶囊四周贴边 −9，约 50 px（约 15dp）外衰减到 0，上下对称，未选中的胶囊没有投影；纯黑页面上都看不到投影。Tsuki 用 Compose `dropShadow`，不偏移，颜色为主题暗色（浅色 onSurface、深色 surface，两者都是黑色，所以黑色页面上不可见）：底栏 26dp 圆角、半径 36.5dp、8.1%；选中胶囊 19dp 圆角、半径 15dp、8.7%。取值按上述读数拟合：底栏用上缘与两端的 9 个读数（下缘落在系统页面底部的渐隐区，读数偏弱，不参与），均方根残差约 0.5 级；胶囊用贴边读数与约 50 px 的消失距离。`dropShadow` 的高斯 σ = 0.577 × 半径 + 0.5 px，投影在轮廓外框之外一个半径处截止（截止处约 1 级的台阶）。实机（2026-11-15）上底栏剖面与系统读数相差都在 ±1.5 级内，反推的 σ 也符合这一换算；选中胶囊贴边到 10dp 的强度与预测相差不到 0.5 级。投影只绘制在轮廓之外，内部不得透过半透明材质使表面发灰；三种后端共用同一投影，不增加测量或触控范围，静止、玻璃态与模糊关闭时都一样。选中胶囊的投影由胶囊所在的行来画，不由胶囊自己画：`MiuixTheme` 把 `LocalOverscrollFactory` 设为 Miuix 的回弹效果，它把横向滚动的内容放在 `clip = true` 的图层里，按行自己的边界（胶囊上方 4dp、下方 10dp）裁剪，胶囊自己画的投影会在那里被切成直线；行在横向滚动之外的一层按各胶囊上报的位置（含横向滚动与回弹位移）画在胶囊之下，只按行的宽度裁剪，上下完整延伸，不增加布局与触控。整个胶囊行画在顶栏背景、顶栏标题与按钮之上，所以投影也压在它们之上，可伸进顶栏底部约 11dp。非概览页上胶囊连同投影一起移出窗口。实机核对时测量了底栏上方 1、6、12、18、24dp，下方 1、3、6dp（再往下是系统手势条）与两端外 6、12dp 处的投影剖面，以及选中胶囊上下左右的逐像素剖面：上下 12dp 处仍有投影、相邻两行之差不超过 1.5 级，未选中胶囊下方没有投影。
- **边缘光效**：参照 HyperOS 4 系统电话应用与主题商店的录屏测量（2026-11-14），玻璃外沿内侧有一圈加色光：白色以 `BlendMode.Plus` 叠加，压在不同亮度的内容上都增加同样的级数，浅色与深色强度相同；整圈画在轮廓内侧（线宽中心向内缩半个线宽），不改变测量、布局与命中区。底栏为均匀一圈，强度 10%、宽 0.6dp。未选中游戏胶囊有方向，宽 0.75dp，按外沿的外法线方向取强度：上下直边 13.5%，左右端点 9%，左上与右下转角 16%，右上与左下转角 9%，其间按角度线性插值。浅色主题的 MiGlass 路径下，材质压在内容上时自带一圈边缘亮度，所以这条路径上各方向的强度都减去 6.2%（下限 0），使叠加后的总亮边与系统一致；深色与 miuix-blur 路径不减。6.2% 按 2026-11-15 第二次实测（胶囊已是底栏材质：浅色 65%、半径 14）取值：原先减去 7.8% 时上直边总亮边 +28.9，低于系统的 +31～+35，因为更浓的底色盖掉了材质自带边缘的一部分。强度随玻璃进度从 0 增强。两者都只在 MiGlass 与 miuix-blur 下绘制，“界面模糊效果”关闭或两种后端都不可用时没有；选中层与选中胶囊没有。部件页切换按钮外框的边缘光效见 C7。实现在 `ui/glass/EdgeLight.kt`。
- 对已经采样的背景结果使用 DstIn 遮罩控制透明度，色调层单独淡入，再绘制前景。禁止给承载采样的容器套整体 alpha。模糊开关、硬件加速及公开支持性判断只在进入宿主或开关变化时计算。
- “界面模糊效果”默认开启，保存于现有 ui SharedPreferences 的 blur 键。关闭，或两种后端都不可用时：顶栏背景改为 surface，随滚动显隐，首页从状态栏底边淡出到操作行底边上方 8dp，不覆盖游戏行，其他页面从操作行底边上方 32dp 淡出到顶栏背景的底边；按钮和底栏为 surfaceContainer 加轻阴影，底栏没有边缘光效；游戏胶囊始终采用静止样式（未选中与选中均为上文的不透明色），没有边缘光效，选中胶囊的投影不变；底栏选中项为 secondaryContainer。回退不改变测量和布局。
- MiGlassCapability 在进程级 lazy 缓存签名／ROM 能力，GlassSession 管理完整初始化、更新与逐项清理；失败实例不重试，View／配置重建才重探测。关闭模糊，或页面在转场结束后被二级页面完全盖住时，移除原生 View 并停止录制；二级页面滑入、滑出的转场进行中，上下两页的玻璃都保持开启（`TransitionGlass`），顶栏与底栏的模糊不会在转场中消失；玻璃是否开启与页面是否接收输入分开判断，转场中仍屏蔽输入；主标签切换复用同一个顶栏操作背景；游戏胶囊在非概览页保持组合以复用原生材质，但移出窗口并从无障碍树隐藏，避免透明的覆盖层拦截下方内容的点击。能力不支持时不创建 AndroidView。许可仍由实例监听，并在 detach 时注销；原生 View 进度为 0 时 alpha=0 且 INVISIBLE，恢复时只改 alpha／可见性，不重新初始化或改变半径。
- **菜单转场例外**：TsukiMenu 内容层的短暂前景模糊是 RenderEffect 的两处用法之一，范围、半径与时长见[开发约束 §6](DEVELOPMENT_CONSTRAINTS.md#6-模糊与-hyperos-原生玻璃)。
- **标题过渡例外**：另一处 RenderEffect 用法是 `TsukiTopBar` 两个标题在折叠／展开过渡中的短暂前景模糊，曲线见 C1，范围与边界见[开发约束 §6](DEVELOPMENT_CONSTRAINTS.md#6-模糊与-hyperos-原生玻璃)。模糊层四周留出透明边距，模糊不会在文字边缘被切成硬边，文字位置不变。
- 圆角材质只放在背景 AndroidView，Compose 前景保持独立；尺寸来自实际布局，位置由 AndroidView 的窗口变换承接，不引入固定采样大画布。边缘光效由 Compose 画在原生材质之上：MiGlass 路径画在背景 AndroidView 之上的兄弟层，miuix-blur 路径画在 `drawBackdrop` 的离屏层合成到页面之后，两条路径都是对最终像素的加色，不改动 MiGlass 的材质参数。顶栏按钮在 MiGlass 下不叠加 Compose 描边，miuix-blur 下保留 1dp 描边。顶栏背景是唯一的矩形 MiGlass 表面，用上文由胶囊配方派生的矩形参数；其余表面是胶囊形与圆形，用胶囊配方。

### 预览与依赖检查

所有 @Preview 位于 `app/src/debug/java/cafe/miafetta/tsuki/ui/preview/ComponentPreviews.kt`。每个小组件一个预览函数，经 `PreviewParameter` 分别以浅色与深色渲染固定假数据；菜单仅预览 ListPopupColumn / DropdownImpl 内容，不创建弹出窗口并套 TsukiAppTheme，不读取 AppState、凭据、存储或网络；舞台预览使用固定内容槽，生产页面统一经 `WidgetPreviewImage` 展示真实位图。`WidgetPreviewStage`、`ScaledWidgetPreview`、`WidgetGalleryItem` 与 `WidgetSheet` 要经组件进程渲染真实位图，`WidgetSheet` 还需要弹层宿主，所以不做预览，由设备场景 `appUi` 覆盖。

Compose tooling 的版本、Material3 排除与 lint 豁免见[架构 §1](ARCHITECTURE_DECISIONS.md#1-依赖)。

## 桌面小部件

RemoteViews 是平台边界，组件进程不加载 Compose。点击已配置小部件的主体进入概览，并切到该小部件绑定的角色（角色已不存在时保持原选择）；点击未配置的小部件进入配置；桌面长按后的编辑进入配置；独立刷新热区只刷新当前实例。Provider、4×2 尺寸、账号／角色绑定、曝光刷新、原生渲染与位图对照、稳定资源 ID 与进度几何受[开发约束 §1](DEVELOPMENT_CONSTRAINTS.md#1-已安装实例兼容)保护。

- 参考尺寸为 360×161.78988dp，整体等比例缩放。刷新文字、顶部同步时间和刷新图标在基准下为 12dp。
- 顶栏文字采用独立 widget_header_text 资源，不改变 miuix_widget_body1。XML、运行时尺寸动作、预览和位图对照保持同步。
- 系统小部件列表的预览（`previewLayout`）是静态示例布局 `status_widget_preview_*`，示例数据为中性占位，不含真实昵称或 UID。`initialLayout` 与首次拉取期间（没有快照的刷新中）显示加载布局 `status_widget_loading_*`：保留卡片背景、摘要格与图标，文字换成半透明占位条，不显示“未知”。加载布局与正式卡共用框架 ID 和尺寸常量：首次渲染前靠自身权重与最小尺寸适应格子，运行时按与正式卡相同的比例逐尺寸缩放，数据到达时不跳变。按小米小部件规范，预览与实际外观一致、加载时显示占位。
- 深色配色独立于 Miuix 默认主题：背景 #353535，摘要格为 19% 黑（#30000000，叠在背景上约 #2B2B2B，浅色实例夜间可透出背景模糊），主文字 #FFFFFF，辅助时间 #C2C2C2，标签 #D6D6D6，进度填充 #D9D9D9，轨道 #878787。刷新文字与图标用森空岛官方小部件“签到”的颜色 #3BB8FF（由真机截图校正估算）。
- 浅色配色：摘要格为 60% 白（#99FFFFFF），让宿主的背景模糊透出；日间刷新仍为 Miuix primary #3482FF。
- 色值是森空岛官方小组件屏幕像素的近似，不复刻纹理，不推断源 alpha 或真实模糊。浅色实例在系统夜间模式下采用整套深色 palette。
- 色彩通过应用时解析的资源动作绑定，避免宿主复用缓存时保留上一模式。预览缓存区分系统模式；预览不能证明宿主背景模糊。
- 以上配色属于《明日方舟》小部件。终末地小部件（`endfield_widget*`，由 `EndfieldCard` 渲染）照官方“明日方舟：终末地数据工具”固定深色，不随系统模式变化，也不声明宿主背景模糊：背景 #444444 叠等高线纹理，面板为 18% 黑（#2E000000）加 10% 白描边，竖条与理智数值为黄色 #FAEE1C，辅助文字 #9E9E9E。预览与加载布局为 `endfield_widget_preview`、`endfield_widget_loading`；文字尺寸以 360dp 宽为基准写在 `values/widget_endfield_dimens.xml`，运行时按部件尺寸等比缩放。位图出处见[素材来源](UI_ASSET_SOURCES.md)。
